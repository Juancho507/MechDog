1️⃣ Introduccion al Proyecto

MechDog es un robot cuadrupedo autonomo desarrollado sobre ROS Noetic con simulacion en Gazebo y visualizacion web via noVNC. El objetivo principal es la navegacion autonoma en entornos con obstaculos utilizando exclusivamente un sensor ultrasonico.

Este informe compara dos algoritmos clasicos de busqueda de caminos —A* (A-Star) y BFS (Breadth-First Search)— aplicados a la navegacion del robot en tres escenarios de dificultad creciente con objetos dispersos.

Arquitectura del sistema:
  • 🐳 Docker multi-stage (base → builder → visualizer)
  • 🌐 noVNC para visualizacion web en http://localhost:6080/vnc.html
  • 🤖 Gazebo Classic para simulacion 3D
  • 🧭 Navigation stack: A*/BFS + DWA + Occupancy Grid + Safe Learning

2️⃣ Algoritmos Implementados

🌟 A* (A-Star)

Tipo: Busqueda informada (heuristica).

Principio: Combina el costo real del camino recorrido (g(n)) con una estimacion heuristica del costo restante (h(n)) para guiar la busqueda hacia la meta. Utiliza una cola de prioridad (min-heap) para explorar primero los nodos mas prometedores.

f(n) = g(n) + w · h(n)

Donde w es el peso heuristico (configurable, tipicamente 1.0) que controla el balance entre optimalidad y velocidad.

Heuristicas disponibles:

  • Manhattan: h(n) = |x₁ - x₂| + |y₁ - y₂| — Apropiada para movimiento en cuadricula con restriccion 4-conectada.
  • Euclidea: h(n) = √((x₁ - x₂)² + (y₁ - y₂)²) — Apropiada para movimiento libre en cualquier direccion.

Caracteristicas:

  • ✅ Encuentra el camino optimo si la heuristica es admisible (no sobrestima)
  • ✅ Mas rapido que BFS porque dirige la busqueda hacia la meta
  • ✅ Menor consumo de memoria que BFS
  • ⚠️ Puede no encontrar solucion si la heuristica sobreestima el costo

Complejidad:

  • Tiempo: O(b^d) en el peor caso, pero tipicamente mucho menor con buena heuristica
  • Espacio: O(b^d) — almacena todos los nodos generados

🌐 BFS (Breadth-First Search)

Tipo: Busqueda no informada (ciega).

Principio: Explora el grafo por niveles, expandiendo primero todos los nodos vecinos antes de pasar al siguiente nivel. Utiliza una cola FIFO (First-In-First-Out) para asegurar que se exploran primero los nodos mas cercanos al origen.

Caracteristicas:

  • ✅ Garantiza encontrar la solucion de menor longitud en numero de pasos
  • ✅ Completo: siempre encuentra una solucion si existe
  • ⚠️ Puede ser muy lento en mapas grandes (explora en todas direcciones)
  • ⚠️ Alto consumo de memoria (almacena todos los nodos del nivel actual)

Complejidad:

  • Tiempo: O(b^d) — expande todos los nodos hasta profundidad d
  • Espacio: O(b^d) — almacena todos los nodos del nivel actual

3️⃣ ¿Por que solo A* y BFS?

Para este proyecto se seleccionaron exclusivamente estos dos algoritmos por las siguientes razones tecnicas y practicas:

Algoritmo ¿Por que NO se incluyo?
DFS (Depth-First Search) No garantiza caminos optimos. Puede ciclar infinitamente. No adecuado para navegacion real donde cada movimiento tiene costo.
Greedy / Hill Climbing Se queda atascado en minimos locales. No garantiza encontrar solucion. Inseguro para robot real.
Q-Learning Requiere cientos de miles de episodios de entrenamiento. Inviable con un solo sensor ultrasonico y sin GPU. El robot real (ESP32) no tiene capacidad para entrenar.
PPO / DQN / RL Requieren redes neuronales, GPU, y grandes volumenes de datos de entrenamiento. Totalmente inviables en ESP32. El riesgo de colisiones durante entrenamiento viola el principio de Safe Learning.
Algoritmos Geneticos Requieren evaluar cientos/miles de generaciones. Computacionalmente costosos. No adecuados para navegacion en tiempo real.
Dijkstra Equivalente a A* con heuristica h(n)=0. A* subsumee a Dijkstra y es mas eficiente.
⚠️ Decision de diseno: A* y BFS son deterministicos, predecibles y garantizan solucion. Esto es critico para Safe Learning — no podemos permitir colisiones durante la fase de exploracion/aprendizaje. Ademas, el ESP32 del MechDog real no tiene recursos para redes neuronales ni aprendizaje por refuerzo.

6️⃣ Safe Learning (Aprendizaje Seguro)

El modulo de Safe Learning es un componente critico que opera en paralelo al planificador para garantizar la integridad fisica del robot. Implementa un sistema de seguridad de tres niveles:

🔴 Critico

Distancia < 0.15m

Parada inmediata

Frenado maximo

🟡 Warning

Distancia < 0.30m

Reduccion de velocidad

Escalado proporcional

🟢 Safe

Distancia > 0.30m

Ejecucion normal

Sin restricciones

Componentes del Safe Learning:

  • Poligono de seguridad dinamico: Se expande proporcionalmente a la velocidad: largo = base_length + v · linear_factor. A mayor velocidad, mayor area de seguridad al frente.
  • Frenado predictivo: Calcula la distancia de frenado necesaria: d = v²/(2·a) + v·t_reaction y la multiplica por un factor de seguridad (1.5~2.0).
  • Deteccion de punto muerto (dead-end): Despues de 3 paradas de emergencia consecutivas, activa el modo de recuperacion.
  • Home Base / Punto Bueno: Si se excede el maximo de recuperaciones, el robot retorna automaticamente al punto de partida.
  • Filtrado de autocolisiones: Ignora lecturas del sensor por debajo de range_min + 0.06m para evitar que las patas del robot disparen falsos positivos.

7️⃣ Punto Bueno (Home Base)

El Punto Bueno o Home Base es la posicion de origen a la que el robot puede retornar si encuentra condiciones inseguras. Implementado en home_base_node.py:

  • Posicion inicial: Se establece en las coordenadas de spawn del robot (tipicamente 0,0).
  • Retorno automatico: Si se superan N intentos de recuperacion consecutivos, se envia automaticamente un goal de retorno al home.
  • Zona segura: Radio de 1.0m alrededor del home donde el robot esta a salvo.
  • Visualizacion: Se publica un marcador verde en RViz para identificar visualmente la posicion del home.

8️⃣ Escenarios de Prueba

A diferencia de un laberinto tradicional (con pasillos y paredes), los escenarios disenados son campos abiertos con obstaculos dispersos que el robot debe analizar y rodear para encontrar la mejor ruta hacia la meta.

🌱 Simple

3 obstaculos

Para validacion basica del sistema. Obstaculos separados con espacio suficiente para maniobrar.

🌿 Medium

8 obstaculos

Dificultad media. Obstaculos colocados en patrones que requieren desviaciones de la linea recta.

🌳 Complex

15 obstaculos

Alta densidad de obstaculos. El robot debe calcular rutas complejas con multiples cambios de direccion.

9️⃣ Conclusiones

⚡ Veredicto Final

Ejecuta experimentos para determinar el ganador entre A* y BFS.

Recomendaciones:

  • A* es la opcion recomendada para el MechDog real por su eficiencia computacional y menor memoria requerida.
  • Safe Learning es indispensable — sin el modulo de seguridad, cualquier planificador puede generar rutas que resulten en colisiones.
  • El Punto Bueno (Home Base) proporciona una red de seguridad adicional permitiendo retirada automatica ante fallos.
  • Para el robot fisico con ESP32, se recomienda A* con heuristica Manhattan y peso 1.0 como configuracion base.
